# Аудит безопасности «АлаДея»

Дата проверки: 31.10.2026. Проверялись публичная статика GitHub Pages и Node-сервер CMS.

## Что проверялось

- HTTP-заголовки и возможность кликджекинга/встраивания;
- XSS через `innerHTML` и данные из `localStorage`;
- внешние ссылки и `target="_blank"`;
- состав репозитория на секреты, `.env`, ключи, дампы БД;
- доступ к служебным файлам через сервер;
- авторизация, серверные сессии, CSRF, rate limit;
- загрузка изображений: тип, размер, путь, перекодирование;
- зависимости и внешние шрифты.

## Найдено и исправлено

1. **На GitHub Pages нет CSP, X-Frame-Options, Referrer-Policy.**  
   Добавлены meta-CSP, `referrer` и frame-busting в `assets/js/boot.js`. На Node-сервере те же политики выставляются HTTP-заголовками, включая `frame-ancestors 'none'` и `X-Frame-Options: DENY`.

2. **Данные корзины из `localStorage` попадали в `innerHTML`.**  
   Добавлены проверка типов, ограничение цены/количества, экранирование и whitelist путей изображений. Подставленный `<img onerror=...>` и `javascript:`-путь отображаются как текст/fallback, код не исполняется. Текст success-сообщения теперь собирается через DOM API, а не `innerHTML`.

3. **Внешняя загрузка Google Fonts.**  
   Шрифты Cormorant Garamond и Manrope скачаны локально (`assets/fonts`, OFL), CSP больше не разрешает сторонние шрифтовые домены, IP посетителя не уходит в Google.

4. **Не было ограничений длины полей.**  
   Добавлены `maxlength` для имени, телефона, адреса и комментариев.

5. **Ссылки `target="_blank"`.**  
   Проверены: используются `rel="noopener noreferrer"`; `window.open` вызывается с `noopener,noreferrer`.

6. **Секреты и служебные файлы.**  
   В репозитории нет `.env`, ключей, токенов, приватных ключей, SQLite/дампов. Node-сервер не раздаёт `server/`, `data/`, `package.json`, `README.md`, `.env` — проверено HTTP-запросами (404).

7. **Админка не защищалась бы одним JS.**  
   Реализованы серверные сессии (хеш токена в БД), scrypt-пароли, CSRF для всех POST, rate limit 5 попыток/15 минут, `HttpOnly`/`SameSite=Lax` cookie, `Secure` в production, `noindex` и `Cache-Control: no-store` для `/admin`.

8. **Загрузка файлов.**  
   Только JPEG/PNG/WebP, проверка фактического формата через `sharp`, лимит 8 МБ, макс. 1600 px, перекодирование в WebP, случайные имена, хранение вне исходников (`data/uploads`), удаление только из `/uploads/`.

9. **Публичная выдача.**  
   `/api/catalog` и SSR отдают только `published = 1`; скрытые товары остаются в админке. Публичный API не содержит административных полей.

10. **Ошибка загрузки корзины.**  
    Из-за обращения к `cleanText`/`safeImagePath` до их инициализации корзина не восстанавливалась после перезагрузки. Функции перенесены выше инициализации; проверено восстановление корзины.

## Остаточные риски

- GitHub Pages не позволяет добавлять произвольные HTTP-заголовки. CSP/referrer заданы мета-тегами, frame-busting компенсирует отсутствие `X-Frame-Options`, но для production нужен Node-сервер с заголовками.
- CSP публичной части разрешает `style-src 'unsafe-inline'` из-за inline style-атрибутов анимаций; `script-src` ограничен `self`.
- Rate limit входа хранится в БД и действует на один инстанс; при переходе на multi-instance нужен общий Redis/БД-лимитер.
- SQLite подходит для одного сервера. Для нескольких инстансов и managed-бэкапов нужен PostgreSQL/Supabase.
- Пароль администратора задаётся при `npm run admin:create`; в репозитории учётных данных нет.

## Проверки

- CSP: 0 нарушений в Chrome, шрифты и изображения загружаются.
- XSS-нагрузка в localStorage: `window.__xss` не выставлен, имя отрисовано текстом, изображение заменено на fallback.
- Админ-сценарий: неавторизованный редирект, вход, создание/редактирование/удаление, фото, категории, скрытие товара, CSRF-отказ, logout.
- Cookie: `HttpOnly; SameSite=Lax; Path=/; Max-Age=43200`.
- Rate limit: 6-я неудачная попытка возвращает 429.
- Служебные пути: `/server/index.mjs`, `/.env`, `/package.json`, `/data-test/aladea.sqlite`, `/README.md` → 404.
