# АлаДея — сайт кондитерской

Одностраничный сайт кондитерской во Владикавказе: витрина, корзина, заказ через WhatsApp и заявка на торт по эскизу.

**Адрес:** Владикавказ, ул. Кирова, 53  
**Телефон / WhatsApp:** 8 (918) 837-80-48  
**Сайт (статическая витрина):** https://youahannn-hash.github.io/aladea-site/

**Репозиторий:** https://github.com/youahannn-hash/aladea-site

**Планируемый домен:** `aladea.ru`

**CMS:** `/admin` на Node-сервере, см. [docs/CMS.md](docs/CMS.md)

**Аудит безопасности:** [docs/SECURITY.md](docs/SECURITY.md)

## Что внутри

- адаптивная главная страница с hero-блоком, витриной, историей, отзывами, доставкой и контактами;
- фильтр каталога по категориям;
- быстрый просмотр товара: описание, количество, добавление в корзину и прямой заказ в WhatsApp;
- корзина с количеством, суммой и сохранением в `localStorage`;
- оформление заказа: имя, телефон, самовывоз/доставка, адрес, дата и комментарий;
- заявка на индивидуальный торт;
- отправка готового заказа в WhatsApp (без бэкенда);
- **CMS `/admin`**: серверная авторизация, товары, категории, загрузка и оптимизация фото, публикация/наличие/акции, поиск, фильтры, сортировка;
- публичная витрина получает товары из БД на Node-сервере; статический GitHub Pages остаётся fallback-версией;
- страницы `privacy.html` и `404.html`;
- SEO-разметка `Bakery` и `FAQPage`, Open Graph, canonical, favicon, web manifest.

Стек публичной части — HTML, CSS и vanilla JavaScript. CMS — Node.js + Express + SQLite (`node:sqlite`) + `sharp`/`multer`. Сборка фронтенда не нужна.

## Локальный запуск

### Публичная версия без CMS

```bash
python -m http.server 4173
```

Откройте `http://127.0.0.1:4173/`.

### Полная версия с CMS

Требуется Node.js 22.9+:

```bash
pnpm install
cp .env.example .env
npm run db:seed
npm run admin:create
npm start
```

- сайт: `http://127.0.0.1:3000/`
- админка: `http://127.0.0.1:3000/admin`
- БД: `data/aladea.sqlite` (в Git не попадает)
- загрузки: `data/uploads` (в Git не попадают)

Сервер при старте сам создаёт схему и заполняет пустую БД текущим каталогом. Администратора нужно создать командой `npm run admin:create`; пароль в коде не хранится.

## Как менять контент

### Товары

Основной способ — `/admin` на Node-сервере: изменения сохраняются в SQLite и сразу попадают на витрину. Статические карточки в `index.html` — fallback для GitHub Pages, если сервер не используется. У каждой fallback-карточки есть data-атрибуты:

```html
<article class="product reveal"
  data-category="cakes"
  data-id="medovik"
  data-name="Медовик"
  data-price="1500"
  data-unit="1,2 кг"
  data-image="assets/img/product-medovik.jpg">
```

- `data-category` — `cakes`, `desserts`, `pastry` или `bouquets`;
- `data-id` — уникальный идентификатор (латиницей, без пробелов);
- `data-price` — число без пробелов и знака рубля;
- `data-unit` — вес или количество;
- `data-image` — путь к фото.

При добавлении товара продублируйте ссылку на изображение в `<img src="...">` и подпись `alt`, а также обновите счётчик `#catalogCount`, если меняете количество.

### Телефон и WhatsApp

Номер встречается в нескольких местах:

1. `WHATSAPP_NUMBER` в `assets/js/main.js` — формат `79188378048`, без `+`;
2. ссылки `tel:+79188378048` и `wa.me/79188378048` в `index.html`, `privacy.html`, `404.html`;
3. видимый текст `8 (918) 837-80-48`.

При смене номера замените все вхождения поиском по проекту.

### Адрес и часы

Адрес и график находятся в `index.html` (контакты, доставка, подвал) и в `privacy.html`. Текущие данные: `Кирова, 53`, `ежедневно 10:00–19:00`. Проверьте их перед публикацией.

### Фотографии

Фотографии в `assets/img/` предоставлены заказчиком. Они уже подобраны под фирменную палитру и стоят в hero, каталоге и блоке «О кондитерской».

Для трёх позиций — шоколадных букетов, эклеров и «Наполеона» — пока стоят брендированные заглушки `placeholder-*.jpg` с подписью «Фото скоро». Когда пришлёте фотографии, замените эти файлы, сохранив имена, или пришлите их мне.

Рекомендации при будущих заменах:

- товары — квадрат от 800×800 px, JPG/WebP, до 250 КБ;
- hero и фото для блока «На заказ» — вертикаль 4:5, около 900×1125 px;
- фото для блока «О кондитерской» — горизонталь 1000×850 px;
- не растягивайте маленькие фото и сохраняйте единый свет и фон.

Имена файлов можно оставить прежними — тогда достаточно заменить файлы, не трогая HTML.

### Цены и состав

Цены, вес и описания в каталоге нужно сверить с актуальным меню: часть взята из баннера, часть указана как демонстрационная. Сейчас в каталоге 12 позиций: медовик, чизкейк «Сан-Себастьян», шоколадный чизкейк, ягодный торт, «Три шоколада», профитроли с вишней, трубочки с карамелью, пончики, круассан с шоколадом, а также шоколадные букеты, эклеры и «Наполеон» — у последних трёх цена по запросу и заглушки вместо фото.

### Формы

Формы не отправляют данные на сервер. После валидации JS собирает текст заказа и открывает WhatsApp с заполненным сообщением. Пользователь сам нажимает «Отправить» в WhatsApp.

Чтобы подключить почту, CRM или Telegram-бота, замените функцию `openWhatsApp` в `assets/js/main.js` на `fetch` к вашему endpoint.

## Публикация на GitHub Pages

GitHub Pages публикует **только статическую витрину**. CMS, SQLite и загрузка фото на Pages не работают: для них нужен Node-сервер (VPS, Railway, Render и т. п.). Статическая версия остаётся запасной и не связана с БД.

Сборка не нужна. Репозиторий уже создан, Pages включён.

1. Откройте **Settings → Pages**.
2. В **Build and deployment → Source** выберите **Deploy from a branch**.
3. Укажите ветку **main** и папку **/ (root)**, сохраните.
4. Через минуту сайт обновится по адресу `https://youahannn-hash.github.io/aladea-site/`.

Сейчас абсолютные ссылки в `index.html` (`og:image`, `og:url`, JSON-LD), `sitemap.xml` и `robots.txt` указывают на технический адрес GitHub Pages. После подключения домена замените их на `https://aladea.ru/...`.

Для своего домена `aladea.ru` добавьте его в **Settings → Pages → Custom domain** и настройте DNS у регистратора. После подключения домена обновите `og:image`, JSON-LD, `sitemap.xml` и `robots.txt` на финальный URL. Файл `CNAME` создавать вручную не нужно, GitHub добавит его сам.

## Доступность и производительность

- есть skip-link, aria-атрибуты, фокус-ловушки в корзине и меню, `prefers-reduced-motion`;
- изображения с `loading="lazy"`, кроме hero;
- нет внешних JS-библиотек;
- шрифты Cormorant Garamond и Manrope хостятся локально, `font-display: swap`.

## Безопасность

- CSP через `<meta http-equiv="Content-Security-Policy">`: только свои скрипты, стили, шрифты и изображения; внешние фреймы и объекты запрещены;
- `Referrer-Policy: strict-origin-when-cross-origin`;
- frame-busting в `assets/js/boot.js` — защита от встраивания сайта в чужой iframe;
- данные корзины из `localStorage` проверяются по типам, ограничиваются по цене/количеству, путь изображения допускается только из `assets/img/`;
- пользовательские значения в корзине экранируются, текст успешной заявки собирается через DOM, а не `innerHTML`;
- поля форм ограничены по длине (`maxlength`);
- внешние ссылки открываются с `rel="noopener noreferrer"`;
- шрифты self-hosted, без передачи IP посетителя в Google Fonts;
- секретов, `.env`, ключей и приватных файлов в репозитории нет.

Ограничение GitHub Pages: платформа не позволяет задавать произвольные HTTP-заголовки (`X-Frame-Options`, `Content-Security-Policy`, `Permissions-Policy`). CSP и referrer заданы мета-тегами; frame-busting компенсирует отсутствие `X-Frame-Options`. На полноценном сервере (этап CMS) эти заголовки должны выставляться сервером — см. `server/` после реализации.
